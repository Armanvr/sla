## 2. Myro (Successeur) + Liu Zhigang

### 2a. Architecture — Successeurs

**Nouveau fichier** `src/components/team/successors.ts` :
- Type `SuccessorId` (union littérale, commence avec `'myro'`)
- Interface `SuccessorData { id, name, image }`
- Constante `SUCCESSORS: SuccessorData[]` avec Myro (`image: '/assets/successors/Myro.png'`)
- Constante `DEFAULT_SUCCESSOR: SuccessorId = 'myro'`

**Nouveau fichier** `src/components/team/SuccessorSelector.tsx` :
- Props : `selected: SuccessorId`, `onChange: (id: SuccessorId) => void`
- Même style visuel que `MonarchSelector` (grille de boutons avec image + nom)

**Nouveau fichier** `src/components/team/PuissanceRemanente.tsx` :
- Toggle "Monarque / Successeur" (2 boutons en haut)
- Affiche `MonarchSelector` ou `SuccessorSelector` selon le mode actif
- Props :
  - `monarchSelected`, `onMonarchChange`
  - `successorSelected`, `onSuccessorChange`
  - `defaultMode?: 'monarch' | 'successor'` (Wind passe `'successor'`)

### 2b. Modifications des pages Teams

`TeamGuideGuildBoss.tsx` et `TeamGuidePowerDestruction.tsx` :
- Remplacer `<MonarchSelector>` par `<PuissanceRemanente>`
- Ajouter état `selectedSuccessor` (init : `DEFAULT_SUCCESSOR`)
- Le `defaultMode` est `'successor'` si `activeElement === 'Wind'`, sinon `'monarch'`
- Le mode se réinitialise au changement d'élément

### 2c. Liu Zhigang — JSON squelette

## 3. Cores SPIRIT forcés — chasseurs Supporter

### Règle

Pour tout chasseur dont `class === "Supporter"`, le slot SPIRIT dans `CoresSection` est verrouillé sur `ferocious-protectors-claw`.

### Implémentation

- **`types.ts`** : aucune modification (le champ `class: string` existe déjà sur `HunterData`)
- **`HunterProfile.tsx`** : passe `hunterClass={data.class}` à `<CoresSection>`
- **`CoresSection.tsx`** :
  - Nouvelle prop optionnelle `hunterClass?: string`
  - Si `hunterClass === 'Supporter'` : le slot spirit est initialisé sur `ferocious-protectors-claw` et le picker est désactivé
  - Affichage visuel : badge `// Obligatoire` ou bordure colorée distincte sur le slot spirit verrouillé
  - Les données JSON des chasseurs ne sont pas modifiées

## 4. Section "Runes et bénédiction"

### 4a. Composant `RunesSection.tsx`

**Nouveau fichier** `src/components/hunter/RunesSection.tsx`

Structure en 2 colonnes côte à côte :

| Colonne gauche | Colonne droite |
|---|---|
| 3 slots Techniques | 4 slots Bénédictions offensives |
| | 4 slots Bénédictions défensives |

Chaque slot est un bouton interactif (style cohérent avec `CoresSection`) affichant `— Vide —` pour l'instant. La structure est prête à recevoir des données (listes de techniques/bénédictions) sans refactoring.

### 4b. Intégration — Fiche Sung Jinwoo

`HunterProfile.tsx` :
- Nouvelle `// SECTION 02 : Runes et bénédiction` insérée **avant** l'actuelle Section 02
- L'ancienne Section 02 "Recommandations pour le build" devient **Section 03**
- La section Runes est rendue si `data.showRunes === true` dans le JSON du chasseur — champ ajouté à `sung-jinwoo.json` et à `HunterData` dans `types.ts` (extensible à d'autres chasseurs sans toucher au composant)

### 4c. Intégration — Pages Teams (Guild Boss + Power & Destruction)

- La section `<RunesSection>` est ajoutée **juste sous** `<JinwooPanel>` (avant le `<hr>` séparateur)
- L'état des runes (`selectedTechniques`, `selectedBlessings`) est local à la page
- Il se réinitialise quand `switchElement` est appelé (comme les armes et les slots chasseurs)
- La section est commune à toutes les configs d'équipe d'un même élément
